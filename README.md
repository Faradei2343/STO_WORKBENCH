# STO WORKBENCH

`STO WORKBENCH` — Windows-приложение на C# WinForms для автоматизации рутинных операций с сервисными листами, детализациями, реестрами и заявками Мурманского филиала.

Приложение объединяет несколько рабочих инструментов в одном интерфейсе:

- сортировка файлов детализаций;
- формирование реестров передачи сервисных листов;
- автозаполнение PDF сервисных листов;
- генерация заявок МФ из Excel-шаблона;
- отправка заявок через Microsoft Outlook;
- проверка и установка обновлений через GitHub Releases;
- многопоточная автоматическая запись отчетников на диск через несколько приводов.

## Возможности

### Сортировка детализаций

Инструмент обрабатывает папку с файлами вида:
```text
det_*.xls
od_*_*.xls
```
По каждому det_*.xls определяется код/идентификатор из имени файла, после чего создается отдельная подпапка и в нее копируются связанные файлы:
```text
det_*.xls
od_*_*.xls
```
Результат сохраняется в папку Downloads пользователя:
```text
C:\Users\%CurrentUser%\Downloads\Сортировка детализаций yyyy-MM-dd
```
## Формирование реестров СЛ
Инструмент создает Excel-реестры передачи сервисных листов на основании файлов det_*.xls.

Поддерживается чтение:
- обычных Excel-файлов через ExcelDataReader;
- XML Spreadsheet ML файлов, которые имеют расширение .xls, но фактически являются XML.

Из файлов извлекаются:
- код ЭО;
- наименование ЭО;
- список номеров сервисных листов.
- Результат формируется в .xlsx через EPPlus.

Пример выходного файла:
```text
Реестр Передачи <Код ЭО>.xlsx
```
## Автозаполнение PDF сервисных листов
Модуль PDFFiller заполняет сервисные листы в PDF:

- ФИО исполнителя;
- оценку;
- дату и время закрытия;
- ФИО заявителя.

Поддерживаются режимы:
- обработка всех выбранных PDF;
- обработка только текущего файла;
- указание своей даты;
- заполнение только месяца и года;
- указание своего заявителя.

Настройки хранятся в файле:
```text
Settings\settings.json
```
После успешной обработки исходный PDF перемещается в архивную папку внутри каталога входящих файлов:
```text
Заполненные dd-MM-yyyy
```

## Генерация заявок МФ
Модуль генерации заявок работает с Excel-шаблоном, в котором есть лист:
```text
Заявка №
```
Приложение ищет ячейку с шаблоном номера заявки:
```text
МФ*
```

Затем для указанного диапазона номеров генерирует:

1. PDF-файл заявки;
2. XLSX-файл заявки без изображений.

Пример:
```text
МФ100.pdf
МФ100.xlsx
МФ101.pdf
МФ101.xlsx
```
## Отправка заявок через Outlook
Модуль отправки формирует и отправляет письма через Microsoft Outlook.

Для каждого номера заявки ищутся файлы:
```text
МФ<number>.pdf
МФ<number>.xlsx
```
Если оба файла найдены, создается письмо с вложениями и отправляется на указанный адрес.

Поддерживается:
- основной получатель;
- получатель в копии;
- диапазон номеров заявок;
- пропуск заявок, для которых не найдены оба файла.

## Автообновление
Приложение проверяет последнюю версию через GitHub Releases:
```text
https://api.github.com/repos/Faradei2343/STO_WORKBENCH/releases/latest
```
Если версия релиза выше текущей версии приложения, отображается окно обновления.
Текущая реализация ожидает .exe файл в assets релиза.
Тег релиза должен иметь формат:
```text
1.2.3.4
```
## Многопоточная запись дисков (Может плохо искал, но фича буквально без аналогов)

Модуль `MultiBurner` предназначен для пакетной записи подготовленных папок на CD/DVD/BD-диски с использованием нескольких приводов одновременно.

### Требуется:
```text
- Windows с поддержкой IMAPI2;
- один или несколько пишущих CD/DVD/BD-приводов;
- чистые диски для записи;
- разрешение записи на оптические носители в локальных или доменных политиках.

Если запись дисков запрещена политиками Windows, модуль может не видеть приводы или завершать запись с ошибкой.
```
### Правила именования файлов
```text
Модуль не требует специального формата имени файлов.

В качестве задания используется каждая подпапка внутри выбранного каталога:

Выбранная папка
├── file001
├── file002
└── file003
```
Сценарий работы:
1. Пользователь выбирает корневую папку, внутри которой лежат подготовленные подпапки.
2. Приложение загружает список подпапок в очередь.
3. Пользователь выбирает доступные пишущие приводы.
4. Для каждого выбранного привода запускается отдельный рабочий поток.
5. Каждый привод берет следующую папку из общей очереди.
6. Приложение открывает лоток привода и ожидает вставки чистого диска.
7. После обнаружения чистого диска запускается запись.
8. После завершения записи лоток открывается, пользователь забирает диск.
9. Привод автоматически берет следующую папку из очереди.
10. Процесс повторяется до полной обработки очереди.
11. Пример:

```text
Исходная папка:
D:\BurnQueue
├── ПАПКА1
├── ПАПКА2
├── ПАПКА3
├── ПАПКА4
├── ПАПКА5
└── ПАПКА6

Приводы:
Drive 1
Drive 2
Drive 3
```
После запуска:
```text
Drive 1 -> ПАПКА1
Drive 2 -> ПАПКА2
Drive 3 -> ПАПКА3

После завершения:
Drive 1 -> ПАПКА4
Drive 2 -> ПАПКА5
Drive 3 -> ПАПКА6
```
Поддерживается:

1. обнаружение пишущих приводов через IMAPI2;
2. одновременная работа нескольких приводов;
3. общая потокобезопасная очередь заданий;
4. запись одной папки на один диск;
5. автоматическое открытие лотка перед вставкой диска;
6. автоматическое открытие лотка после завершения записи;
7. проверка наличия чистого диска;
8. отображение статуса по каждой папке;
9. логирование в интерфейс и файл;
10. системные уведомления после завершения записи или ошибки.

Логи сохраняются в:
```text
C:\ProgramData\MultiDriveBurner\logs
```
Формат записи на диск:
```text
Диск:
└── ПАПКА1
    ├── file1.ext
    ├── file2.ext
    └── subfolder
```
То есть на диск записывается сама выбранная папка со всем содержимым.

В текущей реализации перед запуском выполняется базовая проверка размера папок под типовой DVD-R:
```text
4.3 GiB
```
Если папка больше этого размера, приложение предупреждает пользователя.
